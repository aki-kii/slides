# 決めたこと

定義案（`design-system/patterns-definition.md`、2026-11-17）で本人に確かめたかった6点。本人の指示「止まらずに妥当な方で決めて、決めた内容を DS の文書に残す」（2026-11-18）に従って決めた。本人が違うと言えば直す。

## q1 好みでないパターンはどれか

**決めたこと**: どれも外さずに載せる。

- **理由**: 本人の評は「すごいよい。全部がいいわけではないが、これで作ってみて」（2026-11-18）。どれが好みでないかは言っていないので、外すものを決める材料がない。使ってみて合わないものを外す
- life の記録がなくデッキから拾っただけの型は、各ページにそう書いて区別した（[q5](#q5)）

## q2 紙芝居型の使いどころ

**決めたこと**: デッキの導入と、各部の導入で使う。本編の説明には使わない。

- **理由**: LT #40 の「紙芝居形式なのは導入だけ」（2026-10-18）と、同じ LT #40 で本人と決めた「各部の最初に章扉と紙芝居を入れる」（2026-10-19）は、どちらも「導入で使う」で、部の導入も導入に入る。初心者支部で2部の冒頭に使ったのも同じ使い方
- 載せた所: [紙芝居型](pages.md#page-kamishibai)、[部の頭に導入の紙芝居](flows.md#flow-part-intro)

## q3 「言い切り」は紙芝居型に含めるか

**決めたこと**: 紙芝居型に含める。前置きのない形として扱い、別の ID（page-statement）は作らない。

- **理由**: SKILL.md の紙芝居は「`layout: center` の前置き＋言い切り」で、言い切りのページは同じ組み方から前置きを抜いたもの。どちらも導入で使い、話し言葉で書く。分けると、どちらを選ぶかで迷うだけになる
- 載せた所: [紙芝居型](pages.md#page-kamishibai)。写真も同じ所にまとめた

## q4 章ラベルと色分けした下線は「デッキごとに選ぶ部品」でよいか

**決めたこと**: デッキごとに選ぶ部品にする。

- **理由**: どちらも、使ったデッキ（LT #40）と、本人が「不要」とした初心者支部（2026-10-29）の両方の記録がある。いつも使う・使わないのどちらにも決まっていない
- 載せた所: [部品](parts.md) の表の「使うか」、[色分けした下線](parts.md#part-underline)、[章ラベル](parts.md#part-chapterlabel)

## q5 life に記録のない型（お悩み → 解決、タグ）を入れるか

**決めたこと**: 入れる。ただし「life に記録はなく、デッキから拾った型」と書いて区別する。

- **理由**: cdk-day1 は、本人が好きな雰囲気として挙げたデッキ（SKILL.md「本人が好きな雰囲気: 『最初からCDKで検証』と JawsSonic の資料」）。プラクティス紹介系のテーマの背骨にもなっている
- 載せた所: [お悩み → 解決](pages.md#page-onayami)、[お悩みを1つずつ解決](flows.md#flow-onayami)、[タグ](parts.md#part-tag)

## q6 パターンの名前（ID と日本語名）はこれでよいか

**決めたこと**: 定義案の ID と日本語名をそのまま使う。

- ID の頭は層を表す: `theme-`（全体の型）、`flow-`（構成の型）、`page-`（ページの型）、`part-`（部品）、`base-`（土台）。写真のフォルダ名と同じ
- 変えたのは2つだけ: page-statement は紙芝居型に含めたので無くした（[q3](#q3)）。全体の型を足したので `theme-` の5つ（theme-verification、theme-explainer、theme-intro、theme-practice、theme-experience）を新しく付けた。サイズの決まりは base-size にした

## 見つけた不具合

`@slides/ui` の InlineSvg（`packages/ui/components/InlineSvg.vue`）の CSS が `.inline-svg :deep(svg)` になっていて、図の中に埋め込んだアイコンの `<svg>` にも `width: 100%` が当たる。そのため、`@slides/ui` の InlineSvg を使うデッキ（bgnr-93、continuum、cdkd-talk など）では、AWS のアイコンが図いっぱいに大きく描かれることがある。

- 直していない。公開済みのデッキの見た目が変わるので、本人の確認を待っている
- 写真への影響: [特徴・理由を1つずつ](pages.md#page-one-by-one) の写真（bgnr-93 p.18）が崩れて写っている。注記を付けた。[疑問を湧かせてから解消する](flows.md#flow-question-answer) は前後のページが崩れるので帯にしていない
