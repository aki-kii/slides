# 台本

## Part1 導入

「SOCIインデックスでコンテナの起動を早くしてみた」、というタイトルで話します。よろしくお願いします。

ECSにホストしたコンテナアプリについて、起動時間が遅くて困っていたため改善を図りました。

どんなアプリかというと、Claude Codeと通話できるDiscord botです。

Discord botはボイスチャンネルとテキストチャンネルのどちらにも入れるようにしています。Claude CodeはChannelsという機能でテキストチャンネルに接続しておきます。そこで、ユーザーがボイスチャンネルに入って会話すると、botが文字起こししてテキストチャンネルに投稿されます。すると、文字起こしされたテキストがClaude Code ChannelsによってClaude Codeに渡され、返事をテキストチャンネルに返します。すると、botがClaude Codeからのメッセージをボイスチャンネルで読み上げしてくれる…という仕組みです。

構成としては、Discordのbotとして振る舞うための処理が入ったコンテナ、読み上げ用のVOICEVOXコンテナ、文字起こし用のTranscribe Streamingコンテナの3つがあり、それを1つのECSタスクとしてFargate上に動かしています。

このDiscord botは費用を抑えるために、ずっと起動しっぱなしではなく、使いたい時にタスクを起動して使い終わったら止めるという使い方をしています。

起動時間が長いとClaude Codeへの音声会話をするためのハードルが高くなり、使いたい時も面倒くさくて使わなかったことがあります。具体的には毎回の起動に約77秒かかっていました。

ではまず、どこに時間がかかっているのかを分析しました。改善前の、起動時間の内訳がこちらです。

全体で約77秒かかっていました。そのうち、イメージの取得、いわゆるプルに37.5秒。読み上げコンテナの起動が0.8秒、Discord botコンテナの起動が1.5秒で、残りはその他の起動処理です。

一番大きいのは、イメージの取得ですね。なんでこんなにかかるのかというと、VOICEVOXのコンテナイメージが約1.9GBと、かなり大きいからです。

ということで、まずはこのプルの時間を短くするところから改善していきます。

## Part2 イメージのプルを速くする

まず、どこから手を付けるかです。さっきの内訳で一番大きかったのは、コンテナイメージのプルでした。

理由も分かっていて、読み上げコンテナに使っているVOICEVOXのイメージが約1.9GBと大きいことです。通常、ECSタスクを起動する時は全てのイメージをプルしてからコンテナの起動が始まります。そのため、コンテナのイメージサイズが起動時間に直結します。

コンテナイメージのプルを速くするためには、イメージの軽量化、イメージのキャッシュ、イメージの遅延読み込みがあります。
VOICEVOXはOSSとして提供されているものをそのまま使うため、イメージの軽量化はできない。そして、FargateはECSタスクごとに環境が独立しているためイメージのキャッシュもできません。
そこで、イメージの遅延読み込みをSOCI Snapshotterによって実現していくことにしました。

では、SOCIとは何かです。

SOCI、Seekable OCIは、コンテナイメージを遅延読み込みすることで、コンテナの起動を早くするための技術です。イメージをプルする時に必要最低限のファイルのみ取得してコンテナを起動し、他のファイルはアプリの実行中に必要になった時に取得します。

SOCI Snapshotterを使った遅延読み込みの仕組みは、コンテナイメージのレイヤーに対してインデックスを作成することで実現しています。アプリ実行時に必要なファイルをインデックスを元に取り出せます。

インデックスはコンテナイメージを作り直さずに後付けできます。レイヤーの中身はそのままに対応するファイルの位置をインデックスする仕組みになっています。

仕組みは、レイヤー、span、zTOCという3つの言葉で説明できます。

レイヤーはイメージを構成する層です。コンテナイメージのビルド時にDockerfileに書いてある区切りごとにTARアーカイブを圧縮したもので構成されています。

zTOCはレイヤーのインデックスです。どのファイルが、圧縮されたレイヤーの中のどこにあるかが書いてあります。

spanは、zTOCがレイヤーを区切った単位です。ファイルを取りに行くときは、このspan単位で取得します。

SOCI Snapshotterを使うとコンテナ起動の流れがどう変わるかを見てみます。コンテナの起動は、イメージのプル、コンテナの作成、コンテナの起動、という順に進みます。

遅延読み込みを行わないイメージのプルは、イメージ全体を取得して、レイヤーを全部展開します。ファイルが全部そろってからコンテナの作成を始めます。

SOCIの場合は、イメージのプルでイメージ全体を取得しません。SOCIがイメージのプルで取得しているものは、SOCIインデックスとzTOC、それと10MiB未満の小さいレイヤーだけです。
コンテナの作成は全てのレイヤーを取得していない状態で行います。

そしてコンテナの起動時、アプリがファイルを読むたびに足りないものをzTOCから探して、span単位でレイヤーから探し出し取得します。最初に全てのレイヤーを取得するのではなく、必要になった分から読み込むため遅延読み込みと呼ばれています。

SOCI Snapshotterの遅延読み込みが効果を発揮しやすいのは、圧縮後のサイズが250MiBを超えるコンテナイメージとされています。Discord botコンテナと読み上げコンテナ（VOICEVOX）はこれに当たるので、この2つにSOCIインデックスを適用してみます。

SOCIの適用にはSOCI Index BuilderやSOCI CLIが一般的ですが、CDKのdeploy-time-build ConstructがSOCIインデックスの構築に対応していたので、こちらを利用しました。

SOCIインデックスを入れたあと、ECSタスクの起動にかかる時間を計測してみます。

全体の起動時間は約77秒→約49秒と、かなり縮まりました。
イメージのプルにかかった時間は、なんと37.5秒→3.3秒まで縮まりました。

その代わり、時間がかかるようになった箇所があります。読み上げコンテナ（VOICEVOX）の起動が0.8秒から9.1秒に伸び、Discord botコンテナの起動も1.5秒から4.7秒に伸びています。

これは、イメージをプルした時に最小限のファイルしか取らなかったため、起動時に足りないファイルがあるたびに取りに行くためです。

イメージのプルは圧倒的に速くなりましたが、その代わりにコンテナの起動時間が伸びた形となります。
とはいえ、全体で約29秒も短縮できました！
